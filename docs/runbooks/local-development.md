# Local development

How to run every part of Baked Blessings on your machine, and the routines for day-to-day changes. Commands run from the repo root unless a section says otherwise.

## What runs where
| Component | Started by | Address | Needs |
|---|---|---|---|
| Postgres 17 (`docker-compose.yml`) | `pnpm db:up`, also run by `pnpm dev` | `localhost:55432` | Docker |
| Core packages: `bake-domain`, `ledger`, `contracts` | `tsup --watch` inside `pnpm dev` | rebuilds `dist/` on save | — |
| Storefront (Hydrogen in MiniOxygen) | `pnpm dev` or `pnpm dev:storefront` | http://localhost:3000 (`/graphiql`, `/subrequest-profiler`) | Nothing: uses mock.shop until linked |
| Bakehouse (Shopify React Router app) | `pnpm dev` (local) or `pnpm dev:shopify` (connected) | http://localhost:3001 (`/healthz`); admin pages through the Shopify tunnel | Postgres; a linked app for admin pages |
| Worker (pg-boss) | In the Bakehouse process (`WORKER_MODE=inline`) | — | Arrives in M2 |
| Thank-you checkout extension | `pnpm dev:shopify` | Shopify checkout preview | Generated in the M0 spike |
| Infra (Pulumi, Go) | Not a local service; see [Infra](#infra) | — | Go, Pulumi |

Ports: 3000 storefront, 3001 Bakehouse (pinned in `vite.config.ts` and `shopify.web.toml`), 55432 Postgres, 64999 Bakehouse HMR in local mode.

## First-time setup
1. Install tools. With [mise](https://mise.jdx.dev), `mise install` provides Node 22.20, pnpm 10.34.6, Go 1.26 and Pulumi from `.mise.toml`. Without mise, use Node 22 (fnm and nvm-style tools read `.node-version`), then `corepack enable` for pnpm, plus Go and Pulumi if you'll touch `infra/`.
2. Install and start Docker (Docker Desktop, OrbStack or colima).
3. Run the bootstrap:

   ```bash
   pnpm bootstrap
   ```

   It checks tool versions, installs dependencies, writes `apps/*/.env` from each `.env.example`, starts Postgres, builds the shared packages and applies migrations. It is safe to re-run: it only adds missing keys and fills empty generated secrets, and never changes a value you set.

Don't confuse it with `pnpm setup`, a pnpm built-in that configures pnpm itself.

## Running the apps
### Local mode (no Shopify accounts needed)
```bash
pnpm dev
```

This starts Postgres, then Turborepo runs the storefront, Bakehouse and the package watchers together. Bakehouse applies pending migrations before it starts. Stop everything with Ctrl-C; Postgres keeps running until `pnpm db:down`.

In local mode Bakehouse boots with placeholder Shopify credentials. `/healthz` and the storefront API routes work. Admin pages under `/app` need a real shop session, so they return 410; use connected mode for those.

### Connected mode (linked app and dev store)
Use this for the embedded admin, webhooks and the checkout extension. It needs the [one-time Shopify setup](#connect-to-shopify-one-time). Use two terminals:

```bash
pnpm dev:shopify
```

```bash
pnpm dev:storefront
```

`dev:shopify` starts Postgres, builds the packages Bakehouse depends on, then runs `shopify app dev`. The Shopify CLI opens a tunnel, updates the app URLs, installs the app on the dev store, applies migrations (the `predev` command in `shopify.web.toml`) and serves Bakehouse on port 3001. Press `p` in its terminal to open the app in the admin. Its first run asks which Partner organization, app and store to use.

`dev:storefront` runs everything except Bakehouse: the storefront plus the package watchers. Because Bakehouse stays on port 3001, the storefront's `BAKEHOUSE_API_URL` is the same in both modes.

Don't run `pnpm dev` and `pnpm dev:shopify` at the same time; both start Bakehouse on port 3001.

### Customer accounts (`/account`)
The Customer Account API only accepts a public HTTPS origin, so `/account` doesn't work on `localhost`. Once the storefront is linked, run it through a tunnel:

```bash
pnpm --filter @bb/storefront exec shopify hydrogen dev --codegen --customer-account-push
```

## Environment files
Each app has a committed `.env.example` and a gitignored `.env`:

- `apps/storefront/.env`, read by MiniOxygen. Holds `SESSION_SECRET` (generated by bootstrap), the Bakehouse API URL and signing key, and, once linked, the storefront tokens from `hydrogen env pull`.
- `apps/bakehouse/.env`, read by the dev server and drizzle-kit. Holds `DATABASE_URL`, placeholder Shopify credentials, signing secrets and optional Resend/Twilio keys. Under `pnpm dev:shopify`, values the Shopify CLI injects (API key, secret, app URL, scopes) take precedence over the file.

The storefront's `BAKEHOUSE_KEY_ID:BAKEHOUSE_HMAC_SECRET` must appear in Bakehouse's `STOREFRONT_HMAC_SECRETS`, which is a comma-separated list of `keyId:secret` pairs. The examples ship matching local-only values, so this holds unless you change one side.

`.env` values are for local development only. Staging and production values live in Pulumi config ([infra/README.md](../../infra/README.md)) and never in these files.

**Adding a variable:**
1. Add it to the app's `.env.example` with a safe local default, or leave it empty with a comment.
2. Add it to the Secrets list in [SPEC.md](../SPEC.md) and to `infra/internal/config` if staging and prod need it.
3. Run `pnpm bootstrap` so every checkout picks it up.

## Database
| Task | Command |
|---|---|
| Start / stop Postgres | `pnpm db:up` / `pnpm db:down` (data is kept) |
| Open psql | `pnpm db:psql` |
| Apply migrations | `pnpm db:migrate` |
| Wipe local data and re-migrate | `pnpm db:reset` |

**Changing the schema:**
1. Edit the tables: `apps/bakehouse/app/db/schema.ts` for Bakehouse tables, or `packages/ledger` for ledger tables.
2. Generate a migration:

   ```bash
   pnpm db:generate
   ```

   drizzle-kit may ask whether a column was renamed; answer in the terminal.
3. Review the SQL it wrote to `apps/bakehouse/drizzle/`.
4. Apply it with `pnpm db:migrate`.
5. Commit the schema change and the migration together.

Never edit a migration that has already been applied anywhere; add a new one instead. Deployed containers apply migrations on start (`migrate.mjs`).

## Before you push
```bash
pnpm check
```

This runs the same steps as CI's TypeScript job: build the packages, check the boundaries, then typecheck and test everything. If you touched `infra/`, also run `go vet ./...` and `go test ./...` there. `pnpm lint` exists but isn't enforced in CI yet.

## Running Bakehouse as production does
To reproduce a Render deploy, build the Docker image and run it against local Postgres:

```bash
docker build -f apps/bakehouse/Dockerfile -t baked-blessings-bakehouse:local .
```

```bash
docker run --rm -p 3001:3000 --env-file apps/bakehouse/.env -e DATABASE_URL=postgres://bakehouse:bakehouse@host.docker.internal:55432/bakehouse baked-blessings-bakehouse:local
```

The container applies migrations, then serves on port 3000; the command maps it to http://localhost:3001.

## Connect to Shopify (one time)
1. Create a Shopify Partner account and a development store, then install the Hydrogen channel on the store.
2. Link the storefront and pull its variables. Run `pnpm bootstrap` afterwards, because `env pull` blanks secret values such as `SESSION_SECRET`:

   ```bash
   cd apps/storefront && pnpm exec shopify hydrogen link && pnpm exec shopify hydrogen env pull
   ```

3. Link the Bakehouse app; this fills `client_id` in `shopify.app.toml`. Then set `SHOP_DOMAIN` in `apps/bakehouse/.env` to the dev store:

   ```bash
   cd apps/bakehouse && pnpm exec shopify app config link
   ```

4. Generate the Thank-you page extension (`thank-you-bake-day`, a checkout UI extension):

   ```bash
   cd apps/bakehouse && pnpm exec shopify app generate extension
   ```

## Infra
Pulumi has no local runtime. Unit tests run offline with mocked providers:

```bash
cd infra && go test ./...
```

Previewing against real providers needs the stack configured as in [infra/README.md](../../infra/README.md):

```bash
cd infra && pulumi preview -s staging
```

## Troubleshooting
- **Port already in use.** Find the process with `lsof -nP -iTCP:3001 -sTCP:LISTEN` (or 3000 or 55432). A common cause is `pnpm dev` and `pnpm dev:shopify` both running.
- **Port 55432 is taken by another checkout or worktree.** Compose names its project after the directory, so each checkout starts its own Postgres. Set `BAKEHOUSE_PG_PORT` in your shell and change `DATABASE_URL` in `apps/bakehouse/.env` to match.
- **"Docker is not running" or `ECONNREFUSED` on 55432.** Start Docker, then `pnpm db:up`.
- **"SESSION_SECRET environment variable is not set".** Usually follows `hydrogen env pull`. Run `pnpm bootstrap`.
- **Changes to a package don't show up in an app.** The package watchers run under `pnpm dev` and `pnpm dev:storefront`. Under `pnpm dev:shopify` alone, rebuild with `pnpm turbo run build --filter='./packages/*'`.
- **Node version warning from bootstrap.** CI and Render use Node 22. Run `mise install`, or switch with your Node version manager (`.node-version`).
